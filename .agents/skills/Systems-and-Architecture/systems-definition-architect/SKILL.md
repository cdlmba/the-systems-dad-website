# System Definition Architect: Blueprinting for Presence

Use this skill to convert a messy idea, recurring habit, or business goal into a formal **System Definition**. 

> [!IMPORTANT]
> **Principle 1**: Prioritize clarity over (and before) action. No initiative begins without a defined "System Definition."

## The "Home API" Logic Block

Every system must be defined in the following structure to ensure it serves as a **Lever**, not a burden.

| Layer | Definition | The "Systems Dad" Requirement |
| :--- | :--- | :--- |
| **Input** | The Trigger or Request. | Must be single-point entry (e.g., an automated form, a specific tag, a single inbox). |
| **Logic** | The "Home API" Rules. | If/Then statements that govern the process. Rules must be "designed for reality," not ideals. |
| **Lever** | The Multiplier. | The specific tool (Python, Zapier, AI) that executes the heavy lifting. |
| **Presence** | The ROI Check. | Exactly how many mental cycles or physical minutes are bought back for family focus. |

## Documentation Standards

### 1. CSS-Style Syntax (Optional but Recommended)
For internal "Home API" documentation, use a CSS-like selector style to keep it high-authority and tactical:

```css
.laundry-protocol {
  trigger: sunday-night-audit;
  logic: wash-on-dry-only(.80-capacity);
  lever: automated-alert(google-home);
  presence-roi: 45m-regained;
}
```

### 2. Forbidden Phrases
- "We should try to..." (Weak) -> **"Protocol: [Action]"**
- "Hopefully it saves time..." (Vague) -> **"Target: [X] Minutes Bought Back"**
- "Manual tracking" (Operational Failure) -> **"Lever: [Automation System]"**

## Creative Process
1. **The Clarity Audit**: Define exactly what is being "fixed" and why it currently lacks a system.
2. **The Logic Pass**: Draft the "If/Then" rules of the system.
3. **The Lever Match**: Select the tool (AI, Script, or Physical Process) that scales responsibility, not stress.
4. **The Presence Calculation**: Define the win. If there is no Presence ROI, discard the system.

## Output Requirement
1. **The System Definition Block**: A structured Markdown table or code block.
2. **The Systemic H1**: A clear "Brand" for the system (e.g., "The Friday Shutdown Protocol").
3. **The Logic Gap Warning**: Call out where the system is likely to fail in "Non-Ideal Reality" (Principle 2).

Architect the system now based on the user's objective.
